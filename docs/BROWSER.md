# Browser surface inspection

`browser_surface_review` complements `web_surface_review` with a disposable,
sandboxed Chromium context. The scanner can request it directly; coverage recovery
also schedules it for observed JavaScript-bearing pages. Static and rendered
inventories are combined before choosing GET-parameter checks.

```bash
npm run browser:install
npm run browser:doctor
npm run test:browser
```

The pinned Playwright dependency installs its matching Chromium headless shell.
On Linux, install its system libraries with
`npx --no-install playwright-core install-deps chromium` if necessary. No browser
or local AI model is downloaded during normal CLI startup. Browser checks run
only on demand. The dedicated Linux arsenal installer includes browser setup.

Chromium sandboxing is required. Recent Ubuntu releases may deny user namespaces
for downloaded browsers; follow the [Chromium AppArmor instructions](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md)
with a profile for the **resolved executable path**. Vulnora does not disable the
sandbox or change OS security policy automatically. Browser revisions can change
that path, so rerun the doctor after updating.

## What is recorded

- Forms and inputs generated by JavaScript in the rendered document.
- Actual fetch/XHR URLs, separately from unverified URLs found in script text.
- Authentication boundaries, linked public routes and concrete GET parameters.
- Incomplete responses, blocked requests and observation limits.

Each call renders one entry document and inspects linked pages as text, reusing
responses already received in that call. Other discovered scripted pages are
scheduled separately. One review allows at most 64 managed requests, 8 MiB of
response data and 120 seconds, including browser startup. Parsing retains the
existing 32-response/128-input limits. Unresolved JavaScript coverage stays open;
browser failure does not establish that the application has no inputs.

## Request boundaries

Chromium's Fetch interception sends each request and redirect hop through Vulnora's
existing HTTP controls with native Fetch (no cookie-bearing shell commands),
including scope, excluded hosts, rate limits, risk
exclusions and cancellation. Only same-origin GET/HEAD requests are admitted.
Sensitive/action URL patterns, writes and foreign origins are blocked. A local
deny-only proxy rejects HTTP traffic and CONNECT tunnels that escape interception.
Service workers, WebSockets and downloads are disabled; WebRTC non-proxied UDP
and QUIC are disabled. Normal browser profiles and their cookies are never loaded.
The isolated context can retain response cookies until that review ends.

This is public surface discovery, not an interactive login or exploit verifier.
There are no automated clicks or form submissions. Worker/popup traffic not
intercepted by the inspected page is denied and reported; applications depending
on it may remain incomplete. A quiet network window is only a bounded observation,
not proof that delayed UI states or every route have been explored. Browser-side
restrictions are not an OS network sandbox for independent external scanners.

The browser test suite uses loopback fixtures and real Chromium. It runs separately
from the normal unit suite so unit tests do not silently require or download a
browser. Controlled CI runs both suites explicitly.
